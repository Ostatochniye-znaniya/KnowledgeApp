# Выбор дисциплин программы профиля

Страница: `/csh/hod/disciplines`.

## Данные и ограничения

- `study_program_disciplines(study_program_id, discipline_id)` — явный перечень дисциплин профиля. Составной первичный ключ исключает повторения. Одна дисциплина может входить в несколько профилей.
- Миграция `20261118231136_AddStudyProgramDisciplines` создаёт связь без автоматического заполнения. Принадлежность дисциплины кафедре не определяет её присутствие в программе.
- Перечни заполняются из учебных планов через импорт или SQL. Эта версия хранит один перечень на `StudyProgramId`; отдельные версии по году поступления ещё не моделируются.
- HOD работает только с группами своей кафедры, подтверждёнными к участию в семестре. Дисциплины доступны из программы группы, в том числе с других кафедр и факультетов. Последующая межфакультетская заявка использует существующий процесс.
- Выбор хранится в `testing.discipline_id`. Предел — две разные дисциплины и количество существующих мест тестирования. Допускается промежуточное сохранение нуля или одной дисциплины.
- Ранее выбранные дисциплины сохраняются и отображаются, даже если перечень программы пока пуст или изменился. Старое назначение можно оставить; после удаления его нельзя назначить заново вне программы.
- Нельзя заменить дисциплину, по которой уже появился отчёт, дата/время, период выбора времени, назначение преподавателей или внешняя заявка. Проверка выполняется на сервере; интерфейс показывает блокировку.
- Общая транзакция и блокировка плана сохраняются. Авторизация использует текущий механизм `ICurrentUserProvider`; отдельные изменения авторизации в задачу не входят.

## API

Существующие маршруты сохраняются:

- `GET /GroupDiscipline/GetDepartment` — кафедра пользователя.
- `GET /GroupDiscipline/GetGroups?semesterId=...` — участвующие группы своей кафедры. При отсутствии параметра определяется текущий семестр.
- `GET /GroupDiscipline/GetAvailableDisciplines/{groupId}` — перечень программы группы. Пустой перечень возвращается пустым массивом, без подстановки дисциплин кафедры.
- `PUT /GroupDiscipline/SetDisciplines/{groupId}` — `{ "semesterId": 17, "disciplineIds": [1, 4] }`. Числа в примере условные.

Список групп дополнен `directionCode`, `semesterYear`, `semesterPart`, `availableDisciplinesCount`. Для дисциплин передаются кафедра, факультет, `isInStudyProgram` и `locked`. Клиент сохраняет именно `semesterId` полученной строки.

## Интерфейс

Страница использует общий каркас `main-container`, таблицу `Table`, фильтры `Dropdown`, кнопки `Button`, уведомления `MiniAlert` и `Pagination`.

В таблице сразу видны профиль, группа, выбранные дисциплины и количество выбранных. Доступны поиск по группе/дисциплине и фильтры профиля/состояния. Кнопка или строка открывает общий `Modal`.

В модалке есть поиск по названию, кафедре и факультету, счётчик выбора и общий `CheckBox` размером 18×18. При достижении лимита остальные варианты блокируются. Кафедра и факультет дисциплины видны перед выбором. Закрытие без сохранения не меняет БД.

## Заполнение перечня

Пример для реальных, заранее проверенных идентификаторов:

```sql
INSERT INTO study_program_disciplines (study_program_id, discipline_id)
VALUES (10, 15), (10, 16), (10, 27);
```

Примерные локальные связи для просмотра интерфейса хранятся только в локальной БД и не являются официальным учебным планом. Нельзя массово назначать программе все дисциплины её кафедры: это вернёт прежнюю ошибочную логику.

## Проверки

Флаг `--disciplines-integration` у `KnowledgeApp.Planning.Tests` выполняет миграции и проверки на отдельной временной MySQL-базе, затем удаляет её. Проверяются состав программы, дисциплины других подразделений, чужие группы, максимум две, повторы, прежние назначения, атомарность ошибочных запросов и защита после начала следующего этапа.
