# Проверка электронных отчётов ЛПР

Страница фронта: `/csh/lpr/report`. Таблица, фильтры, статусы и кнопки используют оформление `/csh/dof/documents`. Статическая таблица и заглушка сводных отчётов заменены рабочим списком отчётов преподавателей.

## Процесс

| Действие | `reports.status` | `done_in_electronic_form` | `review_comment` |
|---|---|---|---|
| Загрузка / повторная загрузка преподавателем | `Pending` | `false` | `null` — проверка ещё не выполнена |
| Одобрение ЛПР | `Signed` | `true` | `Нет` |
| Возврат на доработку | `Rejected` | `false` | Обязательное описание замечаний, до 1000 символов |

Решение записывает время и пользователя в `reviewed_at` / `reviewed_by_user_id`. Повторно рассмотреть тот же файл нельзя; исправленный файл снова получает `Pending`. Принятый файл нельзя заменить. Принятие электронного отчёта не означает сдачу бумажного: `all_done` становится `true`, только если сданы обе формы.

Преподаватель уже получает статус и замечания через `TeacherWorkflow/GetReports`. Его страница перечитывает список при возвращении в окно / вкладку. Отдельных email-уведомлений или новых записей в журнале уведомлений эта реализация не создаёт.

## API

Все пути ниже начинаются с `/csh/api/LprReports`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/GetReports` | Загруженные отчёты всех факультетов |
| GET | `/GetFilters` | Факультеты, кафедры, учебные годы и статусы |
| GET | `/Download/{id}?fileVersion=...` | Исходный DOCX / PDF выбранной версии |
| POST | `/Approve/{id}` | Принять электронный отчёт |
| POST | `/Reject/{id}` | Вернуть на доработку |

Фильтры списка: `facultyId`, `departmentId`, `academicYear` (например, `2026/2027`), `status` (`pending`, `signed`, `rejected`). Без фильтров возвращаются загруженные отчёты всех факультетов. `GetFilters` принимает необязательный `facultyId`, чтобы ограничить кафедры и учебные годы выбранным факультетом.

Одобрение:

```json
{ "fileVersion": "значение из строки списка" }
```

Доработка:

```json
{
  "fileVersion": "значение из строки списка",
  "comment": "Уточнить число участников и заполнить выводы по результатам."
}
```

`fileVersion` — хеш ключа загруженного файла, а не дата или идентификатор отчёта. Если преподаватель заменил файл либо отчёт уже рассмотрен, возвращается HTTP 409. Обновление решения дополнительно проверяет исходный ключ файла в SQL, чтобы не принять другой файл при одновременной загрузке.

## Файлы реализации

- `KnowledgeApp.API/Controllers/LprReportsController.cs` — ручки ЛПР.
- `KnowledgeApp.Application/Services/ReportDocumentService.cs` — список, фильтры, скачивание, проверка замечаний и версии файла.
- `KnowledgeApp.Infrastructure/Repositories/ReportDocumentRepository.cs` — общие записи статуса, признаков сдачи и фильтрация отчётов.
- Фронт: `frontend/services/lprReports.ts`, `frontend/app/lpr/report/page.tsx`, `frontend/app/lpr/report/page.module.css`.
- Страница преподавателя: `frontend/app/teacher/report/page.tsx` — обновление списка при возвращении на вкладку и запрет загрузки принятого отчёта.

Новая миграция не требуется: используются существующие поля `reports`. Старые строки массово не переписываются; новые переходы применяются при загрузке и рассмотрении.

Авторство решения использует общий `ICurrentUserProvider`. При входе через ЕУЗ он возвращает локальный ID подтверждённого пользователя из `users`. Переменные `TEST_*` применяются при `MOCK_AUTH_ENABLED=true`. Самостоятельной проверки роли ЛПР в этих ручках пока нет.

## Проверки

Основной набор:

```powershell
dotnet run --project KnowledgeApp/KnowledgeApp.Planning.Tests/KnowledgeApp.Planning.Tests.csproj
```

С флагом `--report-integration` и переменной `LPR_REPORT_TEST_SERVER` проверяется цикл на MySQL. Строка подключения должна разрешать создание тестовой БД. Проверка создаёт БД с уникальным именем `lpr_reports_check_<guid>` и удаляет её в `finally`; рабочая БД и MinIO не используются.
